How it works

Set it up once. Then it listens.

Four steps, and only the first one needs you.

  1. Tell it where you are interviewing

    Company, the job description, and which round it is — technical, system design, or an HR screen. Each one changes how it answers.

  2. Start the session

    It captures your microphone and the other side's audio separately, and labels who said what.

  3. It answers when the question ends

    Automatically, or on ⌘↵. The question is restated first, so you can check it heard you right before you trust the answer.

  4. Your share stays clean

    The window is excluded from screen capture. What the interviewer sees is your screen, without it.

Before the call

It answers as you, not as a chatbot

Give it the company and the role and it specialises on them. Attach your résumé and every answer is grounded in the whole CV, not a search result from it — so “tell me about yourself” walks your career forward in order instead of naming whichever jobs a search happened to surface.

Your other documents work the other way round. They are indexed on your machine and searched per question, so only the passages that answer it are attached — a two-hundred-page handbook never crowds out the thing you were asked.

System design rounds

It draws the architecture while you talk

The diagram is a separate, concurrent request, so the words you speak arrive in about two seconds and never wait for the picture.

The board opens with a core of five to seven boxes and holds the rest back, dimmed — because reproducing an eighteen-node architecture at minute three spends the clock and pre-empts the interviewer. Every box explains itself on hover, and the request path is numbered along the bottom so you can narrate it in order.

The whole interface

Three buttons and a clock

Answer what it just heard, capture the screen, or type instead. The strip above shows what it is hearing; the red clock is how long you have been in the call, and pressing it twice ends the session and frees the models it loaded.

Under the hood

Local where it counts

Speech recognition is NVIDIA's Parakeet TDT, running on your Mac through Apple's MLX. v2 is the default — English only, and the more accurate of the two on technical vocabulary. v3 covers 25 languages when you need them.

Your documents are embedded and searched on-device too. Nothing is indexed in a cloud, and there is no vector database to sign up for — the index lives in the app, next to the documents it came from.

Details

Built for the twenty seconds you actually have

Every one of these exists because something went wrong in a real call without it.

Hears both sides

Your microphone and the interviewer's audio are captured separately and labelled, so it knows which one asked the question.

Invisible to screen sharing

Excluded from capture at the window level. Measured against the same framework Zoom, Meet and Teams use — the overlay is simply absent from the frame.

Answers in about 1.5s

A warm session is kept ready between questions, and the model is picked for how fast it starts speaking rather than how it benchmarks.

Reads your screen

Screenshot the exercise and it answers about what is on it. Several captures work too — two windows, or one long file scrolled.

Speech never leaves your Mac

Parakeet TDT transcribes on-device through Apple MLX — v2 for English, v3 for 25 languages. No audio is uploaded, and nothing reaches disk unless you switch on transcript saving.

Knows your documents

Notes, a spec, a company handbook — indexed on your Mac and searched per question, so the passages that answer it come along and the rest stays out of the way.

Install

One command

Paste it into Terminal. It downloads the current release, checks its signature, installs it to Applications and opens it.

macOS · Apple Silicon
$ curl -fsSL https://github.com/mailtoharutyunyan/phoenix-releases/releases/latest/download/install.sh | bash

macOS will not block it, and there is nothing else to type. Read the script first if you like.

If that returns error: 429
$ curl -fsSL https://cdn.jsdelivr.net/gh/mailtoharutyunyan/phoenix-releases@main/install.sh | bash

A 429 is a GitHub rate limit, not a problem with your Mac. The mirror serves the same script.

FAQ

Questions worth answering honestly

Can the interviewer see it?

Not in a screen share. The window is excluded from screen capture at the OS level, measured against the same capture framework Zoom, Meet and Teams use: the overlay is present in a screenshot with protection off, and completely absent with it on. It is on by default, and a banner appears whenever you turn it off, because forgetting is the one failure this app must not have. It does not hide the app from someone sitting next to you.

Does my audio leave my computer?

Speech recognition always runs on your Mac — no audio is uploaded, ever. The answer itself comes from whichever engine you pick. By default that is the Claude Code CLI on your own subscription, so the question and surrounding transcript go to Anthropic. If you would rather nothing left at all, switch to the bundled local model and it runs entirely offline. The app names the active engine rather than making you guess.

Do I need an API key or a subscription?

No key, ever. If you already have the Claude or Codex CLI installed and signed in, Phoenix uses it. If you do not, it falls back to the local model on its own — nothing breaks, the answers just come from a model on your machine.

Is anything recorded?

A transcript reaches disk only if you switch on “save transcript” for that session, and it is off by default — the transcript contains the other participant's speech, recorded without their consent. Screenshots are temporary and deleted after the answer.

macOS says the app is “damaged”. Is it?

No. Phoenix is not signed with a paid Apple Developer certificate, and “damaged” is simply the wording macOS uses for that. The flag comes from the browser that downloaded it — a download made with curl never gets one, which is why the command above works where double-clicking a browser download does not.

Why do I grant permissions again after every update?

Because without a Developer ID each build is a new identity to macOS's privacy system, so Microphone and Screen Recording have to be granted again. It is expected; the troubleshooting guide explains how to clear the stale entry.
