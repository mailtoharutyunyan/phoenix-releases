How it works

Four steps, then it stays out of the way

You set up a session before the call. During it, Phoenix does the listening.

  1. Tell it where you are interviewing

    Company, the job description, and which kind of round it is — technical, system design, or an HR screen. Each one changes how it answers.

  2. Start the session

    Phoenix captures your microphone and the other side's audio separately, and labels who said what.

  3. It answers when the question ends

    Automatically, or when you press ⌘↵. The question is restated first, so you can confirm it heard the right thing before you trust the answer.

  4. Nothing of it reaches the share

    The window is excluded from screen capture, so what the interviewer sees is your screen without it.

Before the call

It answers as you, not as a chatbot

Give it the company and the role and it specialises on them. Attach your résumé and it answers in your own history — the whole CV goes in, so "tell me about yourself" walks your career forward instead of naming whichever jobs happened to be retrieved.

Reference documents are searched locally and only the relevant parts are attached, so a long handbook does not crowd out the question.

System design rounds

It draws the architecture while you talk

Ask it to design something and the diagram is drawn as a separate, concurrent request — so the words you speak arrive in about two seconds and do not wait for the picture.

The board starts with a core of five to seven boxes and holds the rest back, dimmed, as "say it, draw if asked" — because reproducing an eighteen-node architecture at minute three spends the clock and pre-empts the interviewer. Every box explains itself on hover, and the request path is numbered so you can narrate it in order.

What else

Built for the twenty seconds you actually have

Everything here exists because something went wrong in a real call without it.

🎙️

Hears both sides

Your microphone and the interviewer's audio are captured separately and labelled, so the app knows which one asked the question.

🖥️

Invisible to screen sharing

Excluded from capture at the window level. Verified against the same framework Zoom, Meet and Teams use — the overlay is simply absent from the frame.

⚡

Answers in about 1.5s

A warm session is kept ready between questions, and the model is chosen for how fast it starts speaking rather than how it benchmarks.

📸

Reads your screen

Screenshot the coding exercise and it answers about what is on it. Multiple captures work too — two windows, or one long file scrolled.

🔒

Speech never leaves your Mac

Transcription runs on-device. Nothing is written to disk unless you turn on transcript saving for that session.

🔌

Works offline too

Prefer nothing to leave at all? Switch to the bundled local model. There is always an on-device path, and no feature requires an account.

Install

One command

Paste this into Terminal. It downloads the current release, checks its signature, installs it to Applications and opens it.

macOS · Apple Silicon
$ curl -fsSL https://github.com/mailtoharutyunyan/phoenix-releases/releases/latest/download/install.sh | bash

macOS will not block it and you will not have to type anything else. Read the script first if you like.

If that returns error: 429
$ curl -fsSL https://cdn.jsdelivr.net/gh/mailtoharutyunyan/phoenix-releases@main/install.sh | bash

A 429 is a GitHub rate limit, not a problem with your Mac. The mirror fetches the same script.

FAQ

Questions worth answering honestly

Can the interviewer see it?

Not in a screen share. The window is excluded from screen capture at the OS level, which was measured against the same capture framework Zoom, Meet and Teams use: the overlay is present in a screenshot with protection off, and completely absent with it on. It is on by default, and a banner appears whenever you turn it off, because forgetting is the one failure this app must not have. It does not hide the app from someone sitting next to you.

Does my audio leave my computer?

Speech recognition always runs on your Mac — no audio is uploaded, ever. The answer itself is generated by whichever engine you choose. By default that is the Claude Code CLI running on your own subscription, so the question and the surrounding transcript go to Anthropic; if you would rather nothing left at all, switch to the bundled local model, which runs entirely offline. The app tells you which engine is active rather than making you guess.

Do I need an API key or a subscription?

No key, ever. If you already have a Claude or Codex CLI installed and signed in, Phoenix uses it. If you do not, it falls back to the local model automatically — nothing breaks, answers just come from a model on your machine instead.

Is anything recorded?

A transcript reaches disk only if you switch on "save transcript" for that session, and it is off by default — the transcript contains the other participant's speech, recorded without their consent. Screenshots are temporary and deleted after the answer.

macOS says the app is "damaged". Is it?

No. Phoenix is not signed with a paid Apple Developer certificate, and "damaged" is simply the wording macOS uses for that. The flag is applied by the browser that downloaded it — a download made with curl never gets one, which is why the install command above works and double-clicking a browser download does not.

Why do I have to grant permissions again after an update?

Because each build is a new identity to macOS's privacy system when it is not signed with a Developer ID. Microphone and Screen Recording have to be granted again after each update. It is expected, and the troubleshooting guide explains how to clear the stale entry.
